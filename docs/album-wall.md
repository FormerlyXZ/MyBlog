## 1. 它是什么

**一整块可以拖着走的照片海**，波浪 Banner 是它的「幕布」。

- **滚轮往下 = 掀开幕布**：波浪整块升起，照片海整屏接管。滚轮**只管滚页面**，从不接管画布
- **左键拖动 = 二维平移**：上下左右都能拖，滑到边界有橡皮筋，松手弹回
- **画布比屏幕宽好几倍**：一屏只看得到五六个列，横向还有得拖（`boardWidth` 可调）
- **点一下原地放大**：那张照片变成**整数列宽**、保持原比例；下方照片顺着让开，
  四边只剩一个标准间隙；其余照片压暗，相机把它推到视口正中
- **再点一下进灯箱**：滚轮以光标为中心缩放、拖动查看、左右切换
- **左侧竖向分类栏**：可收起 / 展开，切换时整片重新排列
- **画布外面不是死黑**：星尘 + 星云 + 画布边缘的微光，拖到头会觉得「海还在继续，只是过不去」

排序是**确定的**：`photos[]` 的数组顺序 = 照片海从左到右、从上到下流动的顺序。
刷新、分享链接、筛选后重排，位置都能复现 —— 这是「可 deep-link 到某张图」和「用户知道自己看完了」的前提。

## 2. 交互状态机

```
   ╔══════════════════════════════════════════════════════╗
   ║  curtain  滚轮往下，波浪升起，照片海整屏接管（可逆） ║
   ╚══════════════════════════════════════════════════════╝
                              │
                              ▼
   ┌────────┐  点照片   ┌─────────┐  点同一张  ┌────────┐
   │  idle  │ ────────▶ │  focus  │ ─────────▶ │  zoom  │
   └────────┘           └─────────┘            └────────┘
        ▲                     │                      │
        └────── Esc / 点空白 ──┴────── Esc / 点遮罩 ───┘
                              ▲  点别的照片
                              └──────────────────────
```

| 状态 | 表现 |
|---|---|
| `curtain` | 首屏就是整块 Banner（`100svh`）。往下滚它就自然被顶出视口，滚回来它自然落回来；滚到底就是 `idle` |
| `idle` | 照片海铺满整屏，相机停在画布正中，可任意方向拖 |
| `focus` | 点中那张**原地**放大成 2–3 列宽（横图/方图 3 列、竖图 2 列，保持原比例）、邻居裁短/下移让开、其余照片压暗（`filter: brightness`）、相机同时滑过去居中，底边浮出标题条 |
| `zoom` | 灯箱：黑底、`contain` 显示、滚轮以光标为中心缩放（1×–6×）、放大后可拖动、双击在 1× 与 2.4× 之间切换、← → 切照片、Esc 逐级退回 |

### 手势与快捷键

| 操作 | 桌面（相机模式） | 手机（滚动模式） |
|---|---|---|
| 进出照片墙 | 滚轮上下（掀 / 落幕布） | 页面正常滚动 |
| 平移 | 按住左键拖（二维，带橡皮筋） | 页面正常滚动 |
| 滚轮 | **只滚页面**；到顶到底之后就没有别的了 | 页面正常滚动 |
| 点照片 | 放大 | 放大（并自动滚到视口中央） |
| 点放大的那张 | 进灯箱 | 进灯箱 |

## 3. 排版算法

### 3.1 打包

固定列宽、列对齐、行不对齐（瀑布流）。**不是**简单的「记每列高度」，而是每列维护一份「已占用区间」：

```ts
type Span = [start, end];            // 同一列内按 start 升序

firstFit(col, h, from) → y           // 找第一个 ≥ from 且放得下 h 的位置
occupy(col, y, h)                    // 往区间表里插一段
```

每张照片挑「`firstFit` 返回最小 y」的那一列（同样早就选靠左的）。

**为什么不用「每列高度」**：放大时要在中间挖洞，被洞盖住的列如果只记「当前高度」，
洞上方的空隙就永远填不上了。

打包完之后还会跑一遍 `alignBottom()`：把各列的高度差按「谁更能裁」分摊掉，凑成同一条底线
（见 3.3 ⑤），所以照片海是一个上边和下边都齐的矩形。

### 3.2 列数与画布宽度

```
colW    = clamp(columnWidth * clamp(vw / 1440, 0.72, 1.16), 150, 340)
列数     = round((boardWidth * vw + gap) / (colW + gap))     // 按「几屏宽」算
列数     = min(列数, ceil(Σ(colW/aspect) / (vh * 1.45)))     // 但竖向至少能拖得动 1.45 屏
画布宽   = 列数 * colW + (列数 - 1) * gap
```

第二条很关键：照片少的时候，光按宽度算会得到「又宽又扁」的一条，
竖向根本拖不动 —— 宁可变窄也要让上下有事可做。**只统计当前可见的照片**，
所以筛完只剩 30 张时它会自动收回成四五列，而不是摊成一条横幅。

### 3.3 放大（`packFocus()`）—— 整个引擎最关键的一段

目标：照片**在原地**长大（不会飞走），**四条边都落在网格上**，四周只剩一个标准间隙；
被顶到的那几列顺着让开，并且照片海的上边、下边都是直线。

```
① 基准版面 = 普通排版（确定性，和 idle 里一模一样）
   ⚠ 这一步很关键：以前是「把它摘出去再重排一遍」，摘掉一张会让后面所有照片的
     落列顺序全变，于是整片海都在飞 —— 又乱又看不出因果关系。现在基准不变，
     只有真的被顶到的那 k 列会动（实测 160 张里 4~25 张位置变化，其余连 transform 都不变）
② 宽度取整列：宽 = k 列 + (k-1)·gap，高 = 宽 ÷ 宽高比（**永远原比例，不裁**）
     k 从「focusWidth × 视口宽」反推，上限被 focusMaxHeight 卡一刀，
     下限**硬性 2 列** —— 1 列等于没放大，竖图以前就吃了这个亏
       → 横图 / 方图 3 列（712 宽），竖图 2 列（472 宽、838 高）
     退到 2 列仍然超高就让它超出屏幕（想看清全图交给灯箱），不再压扁或裁掉
③ 方向：默认从它自己的那一列往右长；右边放不下（贴在最右那几列）就改成**往左长**。
   无论哪种，**靠边的那条边钉死不动** —— 照片海不会被顶出边界，只会向内推挤。
   ⚠ 以前是 originCol = clamp(…, 0, cols-k)，最右那一列的照片会被硬拽到左边 k-1 格，
     看起来就是「突然跳了一下」
   纵向同理：沿用 idle 的高度往下长（下面本来就可以无限拖）
④ 逐列开洞（openBand()）：
     · 跨着放大照上边的照片 → **原地裁短**（只改缩略图高度，位置不动），
       底边正好停在「放大照上边 − gap」；裁剩不到 MIN_KEEP(48px) 就不裁，改成整张下移
     · 落在这段里 / 从下面顶进来的 → 整列整体下移，最上面那张正好停在「放大照下边 + gap」
     · 上边还差一点（瀑布流两列本来就错开十几二十像素）→ 把上面那张接到「上边 − gap」
       （拉不超过 1.6 倍，缩略图裁一点），换来一条干干净净的直线
   于是放大照的上、下、左、右四条边都和网格线 / 邻居的边齐平
⑤ 底线（`fitColumn()` / `alignBottom()` / `settleFocusBottom()`）：**不靠整列等比缩放**，
   而是「按每张缩略图能牺牲多少」把高度差分摊掉 —— 见下面的「底线对齐」小节
⑥ 相机和重排**同时**开始（同一个 --gal-dur、同一条缓动曲线），
   放大照在长、邻居在让、镜头在滑，叠成一段连续位移；结束时它正好停在屏幕正中
```

#### 底线对齐（`fitColumn` / `alignBottom` / `settleFocusBottom`）

缩略图是 `object-fit: cover` 的**取景框**：把框改矮/改高只是换了取景范围，图片本身不会变形。
所以高度差根本不需要「整列一起变胖」，直接按「谁更能裁」摊掉就行。

```ts
cropRoom(cell)     // 按原图长宽给出这张能缩多少 / 能长多少
                   //   竖图 9:16 → down 45%（正好就是「9:16 变 1:1」的方裁）、up 32%
                   //   方图      → down 34% / up 30%
                   //   3:2 横图  → down 26% / up 28%（压扁一点就是宽幅取景）
                   //   全景      → down 20% / up 24%
fitColumn(list, y0, bottom, roomScale = 1)
                   // 从 y0 按 8px 的缝重堆，总高正好落在 bottom；
                   // 差值按 roomScale·cropRoom 的权重**按比例**分摊到每张的高度
                   // 返回「没消化掉的差值」（0 = 正好齐），roomScale > 1 是兜底第二档
```

* **idle（`packNormal` 末尾 → `alignBottom`）**：底线不是「最长那列的底边」，而是在
  `[最矮的列底, 最高的列底]` 之间解一个 **minimax** —— 让「裁得最狠的那一列」裁得最少。
  19 列每列只摊 5%~10%，肉眼看不出来；筛完只剩 7 张（4 列里有一列只有 1 张）也照样齐平。
  实测：160 张 / 8 张 / 7 张 / 32 张，各列底边差值都是 **0.0~0.4px**。
* **放大态（`packFocus` 末尾 → `settleFocusBottom`）**：放大照比它原来那个格子高出一截，
  被顶开的那 k 列会往下多伸一段。处理顺序是
  ① 把「放大照下面那些照片」重新摊进基准底线（按上面同一套余量裁）；余量不够再来一档
  `roomScale = 1.8`；② 还不够就把整条放大带（含放大照）**整体上抬** `dy`，上半段跟着压紧
  （`dy` 受「上半段能压出多少」和画布顶双重限制）。于是**放大期间**下边缘也还是直线。
  实测：中间那张 `u≈0.1~0.3`（只摊掉几十像素，`bottom` 增量 0）；右上/左下那些贴边的照样 0。
* **放大会让画布变高只有两种情况**（属于设计取舍，不是 bug）：
  照片本来就贴底 → 走「底边钉死、往上长」（`openBandUp`），这时放大照**两侧那几列**的内容
  必须整个上移让出带宽，它们的底边会停在放大照上边（那片是放大照 + 压暗，看着是一整块）；
  以及照片少到整片海比放大照还矮（7~8 张那种），那点高度只能长出去。

> ⚠ 算「基准版面」时 `alignBottom()` 会连放大照那一列一起对齐（它此时只是普通一张），
> 否则它的起点会比屏幕上实际看到的位置高出一两百像素，点下去先「跳」一下（踩过的坑）。
> 只有 `settleFocusBottom()` 才把放大照排除在外 —— 它永远保持原比例，只整体平移。

**「最下边固定」**：如果这张照片本来就靠照片海的下边缘（往下长会把整片海顶出去），
方向就反过来 —— **底边钉死不动，往上长**，上面那半段按同一比例压紧让出位置
（`openBandUp()`）。所以放大最下面那张时，下边缘那条直线一动不动。

> ⚠ 底线对齐时「基准版面」必须连放大照那一列一起对齐（它此时只是普通一张），
> 只有 `settleFocusBottom()` 才把放大照排除在外 —— 它永远保持原比例，只整体平移。
> 详见上面的「底线对齐」小节。

因为只动被顶到的那几列，整片海不会重排；外面那些照片连 transform 都不变。

> 用户明确允许「所有照片的缩略图比例都可以变，只要最上最下的边框行对齐就行」——
> 实测的规则就是：**被放大那张永远原比例，其余所有缩略图随时可以换取景框**。
> `paint()` 里高度写的是 `rect.h / scale`（缩放前的盒子高），缩放之后正好等于排版高度，
> 比例对不上时 `object-fit: cover` 自动裁切，照片不会变形。

### 3.4 位置怎么落到 DOM

**每个元素只在列宽变化时设一次尺寸**（`colW × colW/aspect`），此后一切都是 `transform`：

```css
transform: translate3d(x, y, 0) scale(rect.w / baseW);
```

照片宽高比固定，所以「等比缩放 + 平移」就能表达任意排版结果。
筛选 / 放大 / 窗口缩放全在合成层上动，**不进 layout、不重绘** —— 160 张图一起变形也能 60fps。

## 4. 相机模型

```ts
cam = { x, y }   // 视口左上角落在画布坐标系的哪一点
stage.style.transform = `translate3d(${-cam.x}px, ${-cam.y}px, 0)`;
```

- **只有左键拖动会动相机**（`pointerdown/move/up` + 位移超过 `DRAG_START` 才算拖）
- **滚轮完全不接管**：没有 `wheel` 监听，滚轮只走页面滚动（也就是掀 / 落幕布）
- **弹性边界**：越界用 `RUBBER = 0.34` 压住，松手 560ms 弹回
- **小画布自动居中**：画布比视口窄时（筛完只剩几张），相机锁在正中间，不贴左上角
- **放大的照片永远能居中**：`camBounds()` 会把「让这张居中的那个 cam 值」并进合法区间，
  所以哪怕照片贴着画布最外那一列，也能被推到正中（越出去的那片交给星尘兜着）

> ⚠ 视口容器必须写 `overflow: clip` 而不是 `overflow: hidden`：
> `hidden` 的容器**仍然是可编程滚动的**，浏览器「把元素滚进视口」之类的逻辑会把它悄悄滚走，
> 整块画布随之错位。

### 4.1 幕布（进入方式）

**幕布是普通滚动内容，不是被 JS 搬上去的**：

```
main
├── .gal-curtain  波浪 Banner，position: relative（100svh 高，z-index 10）
├── .gal          position: fixed; height: 100svh（z-index 自动，在幕布后面）
│   ├── .gal-stars     星尘 canvas
│   ├── .gal-view      视口
│   └── .gal-rail      竖向分类栏（opacity: var(--gal-enter)）
└── .gal-spacer   height: 一屏                     ← 再补一屏，页面正好能滚过 banner
```

- 往下滚：幕布被自然顶出视口，照片海（fixed）纹丝不动 —— 视差感来自「一个动一个不动」
- 往回滚：幕布自然落回来，**永远回得到最上面那张 Banner**
- 滚到底就没有更多可滚的了，于是「滚轮只负责页面」这句话在墙内天然成立，
  不需要任何 preventDefault，也不会和触控板/惯性脚本打架
- 分类栏和提示的透明度跟着 `--gal-enter` 走（脚本只写这个变量）：幕布没升起之前它们不出现

> ⚠ 别再回去用「scroll 事件里写 `translateY(-scrollY)`」那套。scroll 回调里读到的
> `window.scrollY` 常常是**上一帧**的值（平滑滚动、滚动锚定、程序化 scrollTo 都会），
> 幕布就会一直慢一拍 —— 滚到一半往回滚时照片海和底色直接错位，露一大片空白。
>
> ⚠ `.gal` 的高度必须显式写 `height: 100svh`。只写 `inset: 0` 时，某些时刻（祖先临时
> 变成了 fixed 的包含块）它会跟着 main 一起长高（1800 → 2700 → 3600，每次 +一屏），
> `vh` 被带偏 → 列数一路缩水 → 整片墙的照片都挪位。同理，`vh` 只信 `window.innerHeight`，
> 绝不读 `.gal` 的 `clientHeight`。

### 4.2 为什么变暗不用「一层半透明黑」

`.gal-stage` 有 `will-change: transform`（自成层叠上下文），放大那张就算 `z-index` 再高，
也翻不过盖在画布外面的那层黑 —— 整张照片会被一起压暗。所以：

1. `.gal-dim` 只沉在画布**下面**（z-index 0），压星尘和底色；
2. 其余照片各自 `filter: brightness(calc(1 - dim × 0.72)) saturate(.92)`，走合成层。

## 5. 星尘 / 星云（`Dust`）

画布外面那圈不能是死黑，否则「拖到边」就像撞墙。

- 一层**预渲染**的星云（4 个软径向色团，`buildGlow()` 只在 resize / 换主题时重画）
- 一层**浮尘**：`clamp(vw×vh/11000, 50, 180)` 颗，约 14% 是「大颗浮尘」
- 每颗有自己的**视差深度** `d ∈ [0.03, 0.36]`：相机往右走，星尘往左漂一点点，于是有纵深
- 闪烁用 `sin`，`prefers-reduced-motion` 下静止；`document.hidden` 时跳过绘制
- 颜色从主题里**探**一次（隐形探针 `color: oklch(var(--bc))` / `background-color: oklch(var(--p))`），
  深浅主题自动对上；换主题时 `MutationObserver` 监听 `data-theme` 重新探色

## 6. 数据模型

`config/gallery.json`：

```jsonc
{
  "_说明": "给人看的备注，保存时原样保留",
  "settings": {
    "columnWidth": 232,     // 一列的基准宽度（px）
    "gap": 8,               // 图与图的间隙（px）—— 放大时四周用的也是它
    "boardWidth": 3.2,      // 画布横向铺开几屏宽
    "radius": 4,            // 图片圆角（px）
    "focusWidth": 0.52,     // 放大那张的目标宽度（占视口宽度）
    "focusMaxHeight": 0.8,  // 放大那张的高度上限（竖图会被这条卡住）
    "dim": 0.6              // 其余照片压暗多少
  },
  "photos": [
    {
      "id": "g0001",                    // 稳定 id（筛选 / 放大 / ?p= 都用它）
      "src": "/image/gallery/g-01.svg", // 图床 URL / 仓库路径 / 外链，三种都认
      "w": 1200, "h": 900,              // 像素尺寸（排版按它算宽高比）
      "title": "海边",                   // 可选：放大时底部标题条 + 灯箱标题
      "description": "",                // 可选
      "tags": ["旅行", "风景"],          // 可选：分类标签，可多个
      "date": "2026-05-20"              // 可选：灯箱底部信息
    }
  ]
}
```

要点：

- **扁平**：没有「相册」这一层。一张图属于什么分类，完全由 `tags` 决定，
  所以同一张图可以既在「旅行」又在「夜景」里。
- **真实尺寸**：记 `w/h`，宽高比被夹在 0.28–4（超长截图不会把一整列撑爆）。
- **顺序即排版**：数组顺序就是流动顺序，管理面板拖缩略图改的就是它。
- 改完要重启 dev 或重新 build（构建期 `import` 这份 JSON）。
- **仓库里的 `photos` 是空的**：演示用的占位图（`public/image/gallery/`，160 张 SVG）
  已被 `.gitignore` 排除。想本地看演示效果就跑一次 `npm run gen:assets`
  （`scripts/gen-placeholders.mjs`）生成占位图，再自己往 `config/gallery.json` 里加数据；
  真实照片走图床，`/config → 照片墙` 里批量上传就行。

### 旧数据迁移

`config/albums.json`、`public/image/albums/`、`/photo-wall/` 已删除；
旧书签 `/photo-wall/?id=xxx` 由 `astro.config.mjs` 的 `redirects` **301** 到 `/album/`。

## 7. DOM 契约

`gallery-wall.ts` 靠这些属性找元素，**改名要两边一起改**：

| 选择器 | 含义 |
|---|---|
| `[data-gal]` | 舞台根。`data-gal-settings` 是设置 JSON，`data-gal-mode` 由脚本写 |
| `[data-gal-curtain]` | 幕布（里面装着波浪 Banner，**在 `.gal` 外面、参与页面滚动**） |
| `[data-gal-spacer]` | 再撑一屏滚动距离的空块（和 `.gal` 同级，`height` 由脚本写） |
| `[data-gal-stars]` | 星尘 canvas |
| `[data-gal-view]` | 视口（`overflow: clip`，承接指针事件） |
| `[data-gal-stage]` | 画布（相机只动它） |
| `[data-gal-glow]` | 放大那张背后的光晕（在 stage 里，跟着画布走） |
| `[data-gal-dim]` | 变暗层（沉在 stage 下面） |
| `[data-gal-cell]` | 一张照片。带 `data-id / -w / -h / -tags / -src / -title / -desc / -date` |
| `[data-gal-rail]` / `[data-gal-rail-toggle]` | 竖向分类栏 / 展开收起按钮 |
| `[data-gal-tag]` / `[data-gal-count]` | 分类项；`data-gal-tag=""` 是「全部」 |
| `[data-gal-action="reset"]` | 「回到正中」 |
| `[data-gal-hint]` | 底部操作提示 |
| `[data-gal-lb]` + `-canvas / -img / -cap / -count / -prev / -next / -close / -zin / -zout / -fit` | 灯箱 |

运行时写的东西：`<html>` 上的 `gal-camera`（相机模式）、`gal-lb-open`（灯箱打开时锁页面滚动）；
`[data-gal]` 上的 `gal-rail-open` / `gal-focus` / `gal-entered` 和 CSS 变量 `--gal-enter`。

## 8. 管理面板（`/config → 照片墙`）

一份文件管完：`config/gallery.json`。

| 能力 | 说明 |
|---|---|
| 批量上传 | 多选本地图片 → 浏览器里压成 WebP（长边 2000、目标 ~300KB）→ **直传图床 `gallery/`**，仓库里只留 URL |
| 从图床选 | 复用站内媒体库弹窗，挑已经传过的图，一个字节都不重新上传 |
| 排序 | 拖缩略图（原生 HTML5 拖放），顺序 = 照片海流动顺序 |
| 标签 | 单张：卡片里回车即加、点标签即删；批量：选中后「加标签 / 去标签」 |
| 删除 | 单张或批量。**只从 JSON 摘掉**，图床上的文件在提交成功之后才清（`state.trash` → `deleteMedia`） |
| 排版参数 | 7 个滑块实时改，同样要保存才写进仓库 |
| 保存 | 一次 GitHub commit（`commitFiles`），约 1 分钟后生效 |

细节：

- 上传时如果批量标签框里有内容，会顺手打给新照片
- id 重复会被自动换成新 id（重复 id 会让筛选/放大认错人）
- 未授权时面板不加载数据（与 `/write`、`/config` 共用同一份写作令牌）

## 9. 移动端与降级

| 场景 | 行为 |
|---|---|
| 桌面（`min-width:900px` 且 `pointer:fine`） | 相机模式：整屏舞台 + 幕布 + 二维拖拽 |
| 手机 / 触屏 / 窄屏 | 滚动模式：**不接管页面滚动**（手指拖拽和滚动、侧滑返回冲突太狠），照片按屏宽分 2 列，靠页面自己滚；放大时到 88% 屏宽并滚到视口中央；分类栏默认收起 |
| 禁用 JS | `<noscript>` 里的样式把它变成普通三列瀑布 |
| 排版引擎抛异常 | `new Wall()` 抛错时给根节点加 `gal--fallback`，同样是三列瀑布 |
| `prefers-reduced-motion` | 过渡压到 1ms，星尘不闪不跑 |

## 10. 已知取舍 / 还能做什么

- **放大靠画布边缘时的留白**：照片贴着画布最外那一列时，把它居中会把画布边界推进视口，
  露出星尘（不是以前的死黑）。现在靠「星尘 + 星云 + 画布边缘微光」把它解释成「海还在继续」。
  注意照片本身**不会越界**：贴右边那几列放大时是往左长（外边钉死、向内推挤）。
- **整数列宽的代价**：横图 / 方图 3 列（712 宽），竖图 2 列（472 宽、838 高）。
  想让竖图更小可以调「放大宽度占比」；2 列仍然超高时不再裁切，直接让它超出屏幕，
  想看全图点第二次进灯箱。
- **底部对齐的代价**：每列按「谁更能裁」分摊高度差（竖图多担、横图几乎不动，
  常态每张只裁 5%~10%），换来照片海下边一条直线；底部那张放大时底边不动、往上长，
  代价是放大照两侧那几列的内容要整体上移到放大照上边（那片正好被放大照 + 压暗盖住）。
  中段照片放大时，被顶开那几列下面那些照片会再裁一点把下边缘拉回基准线
  （实测只摊掉几十像素；余量不够才整条带往上抬一点）。
- **照片特别少的时候（7~8 张）**：整片海比放大照还矮，那点高度只能长出去 ——
  这时行不对齐的那一列会临时伸出去，属于「没料可用」而不是排版出错。
- **没虚拟化**：几百张以内 `loading="lazy"` 足够。
- **管理面板排序没有移动端方案**：原生 HTML5 拖放在触屏上不生效，但管理只在桌面用。
- **灯箱没有图片预加载**：← → 切图时即取即显（图床有 CDN 缓存，通常够快）。

## 11. 参数速查

| 变量 | 位置 | 作用 |
|---|---|---|
| `--gal-banner-h` | `gallery.css` | 幕布高度，`100svh`（整屏） |
| `--gal-enter` | 脚本写 | 进入进度 0→1；分类栏 / 提示的透明度跟着它 |
| `--gal-dur = 500ms` | `gallery.css` | 相机平移 + 照片长大 / 让位的统一过渡（须与脚本 `CAM_DUR` 一致） |
| `MIN_KEEP = 48` | `gallery-wall.ts` | 开洞时「上边那张最多裁到多矮还留着」 |
| `cropRoom()` | `gallery-wall.ts` | 每张缩略图能缩 / 能长的上限（竖图 45% / 方图 34% / 3:2 26% / 全景 20%） |
| `fitColumn(..., roomScale)` | `gallery-wall.ts` | 底线对齐：把高度差按 `cropRoom × roomScale` 分摊；`1.8` 是放大态兜底第二档 |
| `DRAG_START = 5` | `gallery-wall.ts` | 位移超过它才算拖动，否则算点击 |
| `RUBBER = 0.34` | `gallery-wall.ts` | 越界阻尼 |
| `LB_MAX_ZOOM = 6` | `gallery-wall.ts` | 灯箱最大放大倍数 |
| `SCROLL_QUERY` | `gallery-wall.ts` | 判定窄屏 / 触屏的媒体查询 |
| `RAIL_KEY` | `gallery-wall.ts` | 分类栏展开状态存在 `localStorage` 的键名 |
| `data-gal-grid` | 脚本写（调试） | 一行字符串：`视口 mode colW cols 画布尺寸` |
| `data-gal-focus` | 脚本写（调试） | 放大态诊断：基准底线、带上下边、每列 `b底下张数/p上面张数/l没摊平的差值`、`afford/dy` |
