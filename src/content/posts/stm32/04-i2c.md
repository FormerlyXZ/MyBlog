## 4.1 [I2C]基本电路结构

### 串口的缺点
一个串口只能对接一个串口设备

### I2C总线的电路结构
![](/images/series/stm32/ch4/01.webp)

+ **总线结构**：由 **SCL（串行时钟线）** 和 **SDA（串行数据线）** 两条线组成，支持多主机多从机架构，图中为主机（单片机）与多个从机通信。
+ **硬件配置**：
+ 所有设备的 SCL 和 SDA 引脚必须设置为 **开漏输出** 模式。
+ SCL 和 SDA 总线需要通过上拉电阻连接到 Vdd，以保证总线空闲时为高电平。
+ **从机寻址**：每个从机设备拥有唯一的 **7 位从机地址**，主机通过地址来选择要通信的目标从机。
+ **通信原理**：主机控制 SCL 提供时钟信号，SDA 用于双向数据传输，实现主机与指定从机之间的数据交互。

### 数据线和时钟线
#### 一、时钟信号（SCL - Serial Clock Line）
1. **核心功能**：由**主机**（如STM32单片机）产生并控制，为整个I2C通信提供同步时钟，所有数据传输都在SCL的时钟节拍下完成。
2. **信号特性**：
    - 总线空闲时为**高电平**（由上拉电阻维持）；
    - 主机通过拉低/拉高SCL产生时钟脉冲，控制数据传输节奏；
    - 从机仅能在特定场景下拉低SCL（如从机忙时的“时钟拉伸”），无法主动产生时钟。
3. **关键规则**：数据仅在SCL为**高电平**时稳定有效，SCL为低电平时SDA允许改变电平。

#### 二、数据信号（SDA - Serial Data Line）
1. **核心功能**：用于主机与从机之间的双向数据传输（地址、命令、数据）。
2. **信号特性**：
    - 总线空闲时为**高电平**（由上拉电阻维持）；
    - 开漏输出特性：所有设备的SDA引脚必须配置为开漏模式，通过上拉电阻实现电平上拉，避免总线冲突；
    - 双向性：主机和被选中的从机均可驱动SDA传输数据（主机发地址/命令，从机回传数据）。
3. **关键规则**：
    - SDA的电平变化必须在SCL为**低电平**时进行；
    - SCL为高电平时，SDA电平不可改变，否则视为起始/停止信号。

#### 总结
1. SCL由主机控制，是通信的“同步节拍器”，数据有效性由SCL电平决定；
2. SDA为双向数据线，需开漏输出+上拉电阻，电平仅能在SCL低电平时修改；
3. 两条线空闲时均为高电平，是I2C通信的基础电气特性。

### 起始位和停止位

![](/images/series/stm32/ch4/09.webp)

##### 1. 起始位（Start）

* 条件：SCL 保持高电平（H）时，SDA 由高电平跳变为低电平（↓）。
* 作用：标志一次通信的开始。

##### 2. 停止位（Stop）

* 条件：SCL 保持高电平（H）时，SDA 由低电平跳变为高电平（↑）。
* 作用：标志一次通信的结束。

##### 3. 数据传输规则

* 每个数据字节为 8 位，传输顺序：从最高位（D7）到最低位（D0）。
* 每传输完 1 个字节，接收方必须返回一个 **ACK 应答位**（低电平表示应答，高电平表示非应答）。
* 数据位的变化必须在 SCL 为低电平时进行，SCL 为高电平时 SDA 必须保持稳定，以避免被误判为起始 / 停止位。

### 寻址

##### 1. 通信帧结构

I2C 通信的基本帧格式如下：

```plain
起始位 → 7位从机地址 + R/W# → ACK → 数据字节1 → ACK → … → 数据字节n → ACK → 停止位
```

* **SCL**：串行时钟，由主机产生，同步数据传输。
* **SDA**：串行数据，双向传输，承载地址和数据信息。

***

##### 2. 寻址字节格式

寻址字节共 8 位，结构为：

```plain
[A6 A5 A4 A3 A2 A1 A0][R/W#]
```

* **A6~A0**：7 位从机地址，用于指定通信目标。
* **R/W#**：读写控制位，`0` 表示主机向从机**写**数据，`1` 表示主机从从机**读**数据。

***

##### 3. 示例：寻址 0x78（读操作）

以从机地址 `0x78` 进行读操作为例：

* 7 位地址：`0x3C`（二进制 `0111100`），左移 1 位后得到 `0x78`。
* 读操作：`R/W# = 1`。
* 最终寻址字节：`01111001`（十六进制 `0x79`），对应各位为：

```plain
A6 A5 A4 A3 A2 A1 A0 R/W#
0  1  1  1  1  0  0  1
```

***

##### 4. 应答（ACK）机制

* **定义**：Acknowledge，用于确认数据或地址的成功接收。
* **时序**：主机释放 SDA（拉高），从机将 SDA 拉低，表示应答成功。
* **必要性**：每个字节（地址或数据）传输后，都必须跟随一个 ACK 位，确保通信可靠。

***

### 传输数据

* 地址与读写方向：先由主机发送 7 位从机地址 + R/W# 位，确定通信目标与数据方向。
* 数据传输：地址应答成功后，按方向传输多个数据字节，每个字节后跟随应答位。
* 结束：传输完成后由主机发送停止位，释放总线。

##### 1. 主→从（写操作）传输

* **方向**：主机向从机发送数据（R/W# = 0）。
* **步骤**：
  1. 主机发送地址 + 写位。
  2. 从机应答（ACK）：主机释放 SDA，从机将 SDA 拉低表示确认。
  3. 主机依次发送数据字节，每个字节后从机返回 ACK。
  4. 主机发送停止位，结束传输。

***

##### 2. 主←从（读操作）传输

* **方向**：主机从从机读取数据（R/W# = 1）。
* **步骤**：
  1. 主机发送地址 + 读位。
  2. 从机应答（ACK）。
  3. 从机依次发送数据字节，每个字节后主机返回 ACK：从机释放 SDA，主机将 SDA 拉低表示确认。
  4. 主机可在最后一个字节后发送 NACK（不应答），再发送停止位结束传输。

##### 3. 应答（ACK）机制细节

| **传输方向** | **应答方** | **时序行为** |
| --- | --- | --- |
| 主→从（地址 / 数据） | 从机 | 主机释放 SDA，从机拉低 SDA |
| 主←从（数据） | 主机 | 从机释放 SDA，主机拉低 SDA |

* 应答是传输可靠性的关键，每个字节传输后都必须有对应的 ACK，否则视为传输失败。
* 读操作末尾的 NACK 用于告知从机 “无需再发送数据”，随后主机即可发起停止位。

### I2C速度模式

| 模式名称 | 缩写 | 英文名称 | 速率上限 |
| --- | --- | --- | --- |
| 标准模式 | Sm | Standard Mode | ≤100 kbps |
| 快速模式 | Fm | Fast Mode | ≤400 kbps |
| 快速增强模式 | Fm+ | Fast Mode Plus | ≤1 Mbps |
| 高速模式 | HSm | High Speed Mode | ≤3.4 Mbps |
| 超快模式 | UFm | Ultra Fast Mode | ≤5 Mbps |

#### 补充要点

* **标准 / 快速模式**：是最常用的基础模式，兼容性广泛，适合大多数外设通信。
* **快速增强 / 高速模式**：通过优化总线驱动能力，实现更高带宽，适用于对数据传输速率有更高要求的场景。
* **超快模式**：属于单向传输模式，不支持多主设备和应答机制，主要用于简化的高速数据广播场景。

### 时钟信号的占空比（快速模式）

***

##### 1. 核心特性

* **适用范围**：仅在 I2C **快速模式（Fm）**下支持设置时钟信号（SCL）的占空比，标准模式（Sm）无此配置选项。
* **占空比定义**：以低电平时间 TLow 与高电平时间 THigh 的比值 TLow/THigh 来描述。

##### 2. 典型占空比配置

| **配置示例** | **T****L****o****w****/****T****H****i****g****h** | **波形对应时间** |
| --- | --- | --- |
| 示例 1 | 2/1（一般情况） | 高电平 1 单位，低电平 2 单位 |
| 示例 2 | 16/9 | 高电平 9 单位，低电平 16 单位 |

##### 3. 设计意义

通过调整占空比，可以优化总线在不同负载条件下的信号完整性，确保快速模式下的时序要求得到满足，提升传输稳定性。

### I2C模块的初始化

##### 1. 初始化函数

```c
void I2C_Init(I2C_TypeDef *I2Cx, I2C_InitTypeDef *I2C_InitStruct);
```

* **参数说明**：
  * `I2Cx`：指定要初始化的 I2C 外设，如 `I2C1`、`I2C2`。
  * `I2C_InitStruct`：指向 `I2C_InitTypeDef` 结构体的指针，用于传递初始化参数。
* **作用**：对指定的 I2C 外设进行初始化配置。

***

##### 2. 初始化参数结构体 `I2C_InitTypeDef`

```c
struct I2C_InitTypeDef {
    uint32_t I2C_ClockSpeed;    // 波特率设置
    uint16_t I2C_Mode;          // 工作模式选择
    uint16_t I2C_DutyCycle;     // 快速模式下的时钟占空比
    uint16_t I2C_Ack;           // 与从机模式相关的应答配置
    uint16_t I2C_OwnAddress1;   // 从机模式下的自身地址
    uint16_t I2C_AcknowledgedAddress; // 10位从机地址模式选择
};
```

* **成员详解**：
  * `I2C_ClockSpeed`：设置 I2C 总线波特率，标准模式（Sm）≤100 kbps，快速模式（Fm）≤400 kbps。
  * `I2C_Mode`：选择工作模式，可选：
    * `I2C_Mode_I2C`：标准 I2C 模式
    * `I2C_Mode_SMBusDevice`：系统管理总线设备模式
    * `I2C_Mode_SMBusHost`：系统管理总线主机模式
  * `I2C_DutyCycle`：快速模式下的时钟占空比，可选：
    * `I2C_DutyCycle_16_9`：(T_{Low}/T_{High} = 16/9)
    * `I2C_DutyCycle_2`：(T_{Low}/T_{High} = 2/1)
  * `I2C_Ack`：与从机模式相关，用于配置应答机制。
  * `I2C_OwnAddress1`：从机模式下，设备自身的 I2C 地址。
  * `I2C_AcknowledgedAddress`：用于选择 10 位从机地址模式。

***

#### 初始化代码

```c
// 开启I2C1的时钟，注意是APB1
RCC_APB1PeriphClockCmd(RCC_APB1Periph_I2C1, ENABLE);

// 复位（相当于重启）

// 配置为标准I2C模式
I2C_InitStruct.I2C_Mode = I2C_Mode_I2C;
// 配置快速模式下的时钟占空比为2:1
I2C_InitStruct.I2C_DutyCycle = I2C_DutyCycle_2;

// 初始化I2C1外设
I2C_Init(I2C1, &I2C_InitStruct);

// 使能I2C1外设（闭合总开关）
I2C_Cmd(I2C1, ENABLE);
```

## 4.4 [I2C]写数据

### I2C模块内部结构框图

![](/images/series/stm32/ch4/14.webp)

#### I2C 状态寄存器（SR1/SR2）

##### 1. SR1（状态寄存器1）

SR1 用于反映 I2C 通信过程中的**事件与传输状态**，主要标志位如下：

| 标志位 | 全称 | 含义说明 |
| --- | --- | --- |
| `TxE` | Transmit Data Register Empty | 发送数据寄存器为空，可向寄存器写入下一个待发送字节 |
| `RxNE` | Receive Data Register Not Empty | 接收数据寄存器非空，寄存器中已有可读取的新数据 |
| `BTF` | Byte Transfer Finished | 字节传输完成，当前字节已成功发送/接收，等待下一个字节或结束传输 |
| `SB` | Start Bit | 起始位已发送，主机已成功发起 I2C 起始条件 |
| `ADDR` | Address Sent/Matched | 地址阶段完成，从机地址已发送/匹配成功，进入数据传输阶段 |
| `AF` | Acknowledge Failure | 应答失败，传输后未收到对方应答信号，通常表示从机无响应或地址不匹配 |

***

##### 2. SR2（状态寄存器2）

SR2 用于反映 I2C 总线及外设的**整体工作状态**，核心标志位：

| 标志位 | 全称 | 含义说明 |
| --- | --- | --- |
| `BUSY` | Bus Busy | 总线忙状态，标识 I2C 总线正被占用（起始位已发送、停止位未发送的阶段） |
| … | 其他状态位 | 包含从机模式地址匹配、多主机竞争等额外状态信息（图中以“…”省略展示） |

***

##### 3. 寄存器作用

* **时序控制**：程序通过轮询/中断方式检查 SR1/SR2 标志位，判断通信进度（如起始位是否发送、地址是否应答、数据是否传输完成），是实现 I2C 读写时序的核心依据。
* **错误检测**：通过 `AF` 等标志位快速定位通信故障（如无应答、总线冲突），便于异常处理。

***

### 数据发送过程简介

##### I2C 数据发送过程（主机写模式）

1. **起始与寻址阶段**：\
   主机先发送 **START 起始信号**，接着送出 7 位从机地址 + 写控制位（R/W#=0），等待从机返回 ACK 应答，确认通信目标。
2. **数据传输阶段**：
   * 主机将待发送字节写入**发送数据寄存器**，数据经内部移位寄存器逐位发送到 SDA 总线。
   * 每发送完 1 字节，等待从机返回 ACK 应答；若应答成功，继续发送下一字节（重复“写寄存器→发送→等待ACK”流程）。
   * 状态寄存器 SR1 会通过 `TxE`（发送寄存器空）、`BTF`（字节传输完成）等标志位，同步传输进度。
3. **结束阶段**：\
   所有数据发送完毕后，主机发送 **STOP 停止信号**，释放 I2C 总线，本次通信结束。

***

### 等待总线空闲

#### My_I2C_SendBytes

```c
int My_I2C_SendBytes(I2C_TypeDef *I2Cx,  // I2C接口的名称（如I2C1、I2C2）
                     uint8_t Addr,       // 从机地址，靠左（7位地址左移1位，最低位为0表示写操作）
                     uint8_t *pData,     // 指向要发送数据的缓冲区指针
                     uint16_t Size);     // 要发送的数据字节数量
```

**错误码对应**：

* <code>0</code>：全部数据发送完成且收到从机 ACK，流程正常结束。
* <code>-1</code>：起始条件或地址阶段未收到从机 ACK，属于**寻址失败**。
* <code>-2</code>：数据发送阶段未收到从机 ACK，属于**数据被拒绝**。

```c
int My_I2C_SendBytes(I2C_TypeDef *I2Cx, uint8_t Addr, uint8_t *pData, uint16_t Size);

int My_I2C_SendBytes(I2C_TypeDef *I2Cx, uint8_t Addr, uint8_t *pData, uint16_t Size)
{
```

#### My_I2C_ReceiveBytes

```c
int My_I2C_ReceiveBytes(I2C_TypeDef *I2Cx,  // I2C接口的名称
```

说明：

1. 视频里注释写的是 “要发送的数据的数量”，结合函数作用 “从从机读取若干个字节”，这里应该是笔误，实际是**要接收的数据字节数**。
2. 函数返回值定义：<code>0</code> 表示读取成功，<code>-1</code> 表示寻址失败。

```c

int My_I2C_ReceiveBytes(I2C_TypeDef *I2Cx, uint8_t Addr, uint8_t *pBuffer, uint16_t Size)
{
    // #1. 发送起始位
    I2C_GenerateSTART(I2Cx, ENABLE);

    while(I2C_GetFlagStatus(I2Cx, I2C_FLAG_SB) == RESET);

    // #2. 寻址阶段
    I2C_ClearFlag(I2Cx, I2C_FLAG_AF);
    I2C_SendData(I2Cx, Addr | 0x01);

    while(1)
    {
        if(I2C_GetFlagStatus(I2Cx, I2C_FLAG_AF) == SET)
        {
            I2C_GenerateSTOP(I2Cx, ENABLE);
            return -1; // 寻址失败
        }
    
        if(I2C_GetFlagStatus(I2Cx, I2C_FLAG_ADDR) == SET)
        {
            break;
        }
    }

    // #3. 接收数据
    if(Size == 1){
    // 清除ADDR
    I2C_ReadRegister(I2Cx, I2C_Register_SR1);
    I2C_ReadRegister(I2Cx, I2C_Register_SR2);

    // 向ACK写0
    I2C_AcknowledgeConfig(I2Cx, DISABLE);

    // 发送停止位
    I2C_GenerateSTOP(I2Cx, ENABLE);

    // 等待RxNE置位
    while(I2C_GetFlagStatus(I2Cx, I2C_FLAG_RXNE) == RESET);

    // 读取数据
    pBuffer[0] = I2C_ReceiveData(I2Cx);
    }
    else if(Size == 2){
    // 清除ADDR标志位
    I2C_ReadRegister(I2Cx, I2C_Register_SR1);
    I2C_ReadRegister(I2Cx, I2C_Register_SR2);

    // ACK=1
    I2C_AcknowledgeConfig(I2Cx, ENABLE);

    // 等待接收完成
    while(I2C_GetFlagStatus(I2Cx, I2C_FLAG_RXNE) == RESET);

    // 读取第一个字节
    pBuffer[0] = I2C_ReceiveData(I2Cx);

    // ACK=0  STOP=1
    I2C_AcknowledgeConfig(I2Cx, DISABLE);
    I2C_GenerateSTOP(I2Cx, ENABLE);

    // 等待接收完成
    while(I2C_GetFlagStatus(I2Cx, I2C_FLAG_RXNE) == RESET);

    pBuffer[1] = I2C_ReceiveData(I2Cx);
    }
    else{
    // 清除ADDR标志位
    I2C_ReadRegister(I2Cx, I2C_Register_SR1);
    I2C_ReadRegister(I2Cx, I2C_Register_SR2);

    // ACK=1
    I2C_AcknowledgeConfig(I2Cx, ENABLE);

    for(uint16_t i=0; i<Size-1; i++)
    {
        // 等待接收完成
        while(I2C_GetFlagStatus(I2Cx, I2C_FLAG_RXNE) == RESET);
        // 读取数据
        pBuffer[i] = I2C_ReceiveData(I2Cx);
    }
    
    // ACK=0
    I2C_AcknowledgeConfig(I2Cx, DISABLE);
    I2C_GenerateSTOP(I2Cx, ENABLE);
    
    // 等待接收完成
    while(I2C_GetFlagStatus(I2Cx, I2C_FLAG_RXNE) == RESET);

    pBuffer[Size-1] = I2C_ReceiveData(I2Cx);
    }

    return 0;
}
```

### 数据读取的流程

![](/images/series/stm32/ch4/15.webp)

#### 时序概览

```plain
起始位 → 7位地址+RW#(读) → ACK → 接收第1字节→ACK → ... → 接收第n字节→NACK → 停止位
```

* **RW#**：读操作时地址最低位必须为 `1`（即 `Addr | 0x01`）
* **ACK**：主机接收每字节后，需回复应答（除最后一字节外）
* **NACK**：接收最后一字节后，主机必须回复非应答，触发从机结束发送

### 发送起始位和地址

#### 总线空闲检测 + 发送起始位

| 操作 | 关键函数/标志位 | 说明 |
| --- | --- | --- |
| 等待总线空闲 | `while(I2C_GetFlagStatus(I2Cx, I2C_FLAG_BUSY) == SET)` | 避免总线忙时通信冲突 |
| 生成起始位 | `I2C_GenerateSTART(I2Cx, ENABLE)` | 发起I2C通信起始信号 |
| 等待起始位完成 | `while(I2C_GetFlagStatus(I2Cx, I2C_FLAG_SB) == RESET)` | 等待EV5事件（起始位发送完成） |

#### 寻址阶段（读模式）

| 操作 | 关键代码/标志位 | 说明 |
| --- | --- | --- |
| 清除旧错误标志 | `I2C_ClearFlag(I2Cx, I2C_FLAG_AF)` | 清零应答失败标志，防止误判 |
| 发送地址+读位 | <code>I2C_SendData(I2Cx, Addr | 0x01)</code> |
| 轮询寻址结果 | 死循环检测 `I2C_FLAG_ADDR`/`I2C_FLAG_AF` | 超时保护+错误处理：   `ADDR=SET`：寻址成功，跳出循环   `AF=SET`：寻址失败，发停止位返回-1 |
| 清除ADDR标志 | `(void)I2C_ReadRegister(I2Cx, I2C_Register_SR1);`   `(void)I2C_ReadRegister(I2Cx, I2C_Register_SR2);` | **必须读SR1+SR2**清除ADDR标志，否则状态机卡死 |

### 如何发送ACK和NAK

#### 通用规则

* 前 `n-1` 字节：接收后**回复ACK**，通知从机继续发送下一字节
* 第 `n` 字节：接收后**回复NACK**，通知从机停止发送（触发停止位）

#### 接收前 n-1 字节（带ACK）

```c
// 示例：接收单字节（前n-1字节逻辑）
while(1)
{
    // 超时保护
    if(--timeout == 0) { I2C_GenerateSTOP(I2Cx, ENABLE); return -2; }
    // 等待接收数据寄存器非空（RXNE=SET）
    if(I2C_GetFlagStatus(I2Cx, I2C_FLAG_RXNE) == SET)
    {
        *pBuffer++ = I2C_ReceiveData(I2Cx); // 读取数据
        I2C_AcknowledgeConfig(I2Cx, ENABLE); // 开启ACK，准备接收下一字节
        break;
    }
    // 应答失败检测
    if(I2C_GetFlagStatus(I2Cx, I2C_FLAG_AF) == SET)
    {
        I2C_ClearFlag(I2Cx, I2C_FLAG_AF);
        I2C_GenerateSTOP(I2Cx, ENABLE);
        return -2;
    }
}
```

#### 接收最后 1 字节（带NACK）

```c
// 示例：接收最后一字节
while(1)
{
    if(--timeout == 0) { I2C_GenerateSTOP(I2Cx, ENABLE); return -2; }
    if(I2C_GetFlagStatus(I2Cx, I2C_FLAG_RXNE) == SET)
    {
        *pBuffer++ = I2C_ReceiveData(I2Cx); // 读取最后一字节
        I2C_AcknowledgeConfig(I2Cx, DISABLE); // 关闭ACK，准备发NACK
        break;
    }
    if(I2C_GetFlagStatus(I2Cx, I2C_FLAG_AF) == SET)
    {
        I2C_ClearFlag(I2Cx, I2C_FLAG_AF);
        I2C_GenerateSTOP(I2Cx, ENABLE);
        return -2;
    }
}
```

### 如何发送停止位

#### 发送停止位

```c
I2C_GenerateSTOP(I2Cx, ENABLE); // 触发I2C停止位，结束通信
return 0; // 读取成功
```

#### 注意事项

1. **地址位必须正确**：读操作时地址最低位一定是`1`（`Addr | 0x01`），写操作是`0`（`Addr & 0xFE`），两者不能混淆。
2. **ADDR标志必清除**：仅读SR1+SR2无法清除，必须连续读取两个寄存器（SR1+SR2），否则下一次I2C操作会卡死。
3. **NACK是最后一步**：接收最后一字节后**必须先关ACK**，再发停止位，否则从机会持续等待应答，导致通信异常。
4. **超时保护不可少**：所有死循环必须加`timeout`计数，避免从机无响应时程序永久卡死。
5. **AF标志必清除**：检测到`AF`（应答失败）后，必须用`I2C_ClearFlag`清除，否则后续通信会被错误标志干扰。

#### 错误码规范

| 返回值 | 含义 | 场景 |
| --- | --- | --- |
| `0` | 读取成功 | 所有字节正常接收完成 |
| `-1` | 寻址失败 | 起始位/地址阶段未收到从机ACK |
| `-2` | 数据接收失败 | 接收过程中应答失败/超时 |
| `-3` | 参数非法 | 空指针/空缓冲区/无效外设 |

```c
        if(I2C_GetFlagStatus(I2Cx, I2C_FLAG_ADDR) == SET)
        {
            break;
        }
        if(I2C_GetFlagStatus(I2Cx, I2C_FLAG_AF) == SET)
        {
            I2C_GenerateSTOP(I2Cx, ENABLE);
            return -1; // 寻址失败
        }
    }

    // 清除ADDR
    I2C_ReadRegister(I2Cx, I2C_Register_SR1);
    I2C_ReadRegister(I2Cx, I2C_Register_SR2);

    // #4. 发送数据
    for(uint16_t i=0; i<Size; i++)
    {
        while(1)
        {
            if(I2C_GetFlagStatus(I2Cx, I2C_FLAG_AF) == SET)
            {
                I2C_GenerateSTOP(I2Cx, ENABLE);
                return -2;	// 数据拒收
            }
            if(I2C_GetFlagStatus(I2Cx, I2C_FLAG_TXE) == SET)
            {
                break;
            }
        }
    
        I2C_SendData(I2Cx, pData[i]);
    }

    while(1)
    {
        if(I2C_GetFlagStatus(I2Cx, I2C_FLAG_AF) == SET)
        {
            I2C_GenerateSTOP(I2Cx, ENABLE);
            return -2; // 数据被拒收
        }
    
        if(I2C_GetFlagStatus(I2Cx, I2C_FLAG_BTF) == SET)
        {
            break;
        }
    }

    // #5. 发送停止位
    I2C_GenerateSTOP(I2Cx, ENABLE);
    return 0; // 成功
}

int My_I2C_ReceiveBytes(I2C_TypeDef *I2Cx, uint8_t Addr, uint8_t *pBuffer, uint16_t Size)
{
    // #1. 发送起始位
    I2C_GenerateSTART(I2Cx, ENABLE);

    while(I2C_GetFlagStatus(I2Cx, I2C_FLAG_SB) == RESET);

    // #2. 寻址阶段
    I2C_ClearFlag(I2Cx, I2C_FLAG_AF);
    I2C_SendData(I2Cx, Addr | 0x01);

    while(1)
    {
        if(I2C_GetFlagStatus(I2Cx, I2C_FLAG_AF) == SET)
        {
            I2C_GenerateSTOP(I2Cx, ENABLE);
            return -1; // 寻址失败
        }
    
        if(I2C_GetFlagStatus(I2Cx, I2C_FLAG_ADDR) == SET)
        {
            break;
        }
    }

    // #3. 接收数据
    if(Size == 1){
    // 清除ADDR
    I2C_ReadRegister(I2Cx, I2C_Register_SR1);
    I2C_ReadRegister(I2Cx, I2C_Register_SR2);

    // 向ACK写0
    I2C_AcknowledgeConfig(I2Cx, DISABLE);

    // 发送停止位
    I2C_GenerateSTOP(I2Cx, ENABLE);

    // 等待RxNE置位
    while(I2C_GetFlagStatus(I2Cx, I2C_FLAG_RXNE) == RESET);

    // 读取数据
    pBuffer[0] = I2C_ReceiveData(I2Cx);
    }
    else if(Size == 2){
    // 清除ADDR标志位
    I2C_ReadRegister(I2Cx, I2C_Register_SR1);
    I2C_ReadRegister(I2Cx, I2C_Register_SR2);

    // ACK=1
    I2C_AcknowledgeConfig(I2Cx, ENABLE);

    // 等待接收完成
    while(I2C_GetFlagStatus(I2Cx, I2C_FLAG_RXNE) == RESET);

    // 读取第一个字节
    pBuffer[0] = I2C_ReceiveData(I2Cx);

    // ACK=0  STOP=1
    I2C_AcknowledgeConfig(I2Cx, DISABLE);
    I2C_GenerateSTOP(I2Cx, ENABLE);

    // 等待接收完成
    while(I2C_GetFlagStatus(I2Cx, I2C_FLAG_RXNE) == RESET);

    pBuffer[1] = I2C_ReceiveData(I2Cx);
    }
    else{
    // 清除ADDR标志位
    I2C_ReadRegister(I2Cx, I2C_Register_SR1);
    I2C_ReadRegister(I2Cx, I2C_Register_SR2);

    // ACK=1
    I2C_AcknowledgeConfig(I2Cx, ENABLE);

    for(uint16_t i=0; i<Size-1; i++)
    {
        // 等待接收完成
        while(I2C_GetFlagStatus(I2Cx, I2C_FLAG_RXNE) == RESET);
        // 读取数据
        pBuffer[i] = I2C_ReceiveData(I2Cx);
    }
    
    // ACK=0
    I2C_AcknowledgeConfig(I2Cx, DISABLE);
    I2C_GenerateSTOP(I2Cx, ENABLE);
    
    // 等待接收完成
    while(I2C_GetFlagStatus(I2Cx, I2C_FLAG_RXNE) == RESET);

    pBuffer[Size-1] = I2C_ReceiveData(I2Cx);
    }

    return 0;
}

{

    GPIO_InitTypeDef GPIO_InitStruct;

    GPIO_InitStruct.GPIO_Pin = GPIO_Pin_13;
    GPIO_InitStruct.GPIO_Mode = GPIO_Mode_Out_OD;
    GPIO_InitStruct.GPIO_Speed = GPIO_Speed_2MHz;
```

### OLED的基本原理

![](/images/series/stm32/ch4/20.webp)

* **自发光**：OLED 由有机发光材料制成，**不需要背光**，给对应像素通电就会自己发光。
* **点阵成像**：屏幕由无数个微小像素点组成，控制每个像素**亮 / 灭**，就能拼出文字、图标、图形。
* **驱动方式**：通过驱动芯片（如 SSD1306）接收指令，按行 / 列选中像素，决定哪些点亮、哪些灭，形成完整画面。

#### OLED编程接口

1. OLED 初始化函数接口

```c
int OLED_Init(OLED_TypeDef *OLED,        // 所使用的OLED实例指针
              OLED_InitTypeDef *OLED_InitStruct); // OLED初始化参数结构体指针
```

* **功能**：对 OLED 显示器进行硬件与软件初始化
* **参数**：
* <code>OLED</code>：指向具体 OLED 设备实例的指针
* <code>OLED_InitStruct</code>：包含初始化配置（如 I2C 回调函数）的结构体指针
* **返回值**：<code>int</code> 类型，通常用于表示初始化成功 / 失败状态

2. 初始化参数结构体与 I2C 回调函数接口

```c
struct OLED_InitTypeDef {
    // I2C写数据回调函数指针
    int (*i2c_write_cb)(uint8_t addr, const uint8_t *pdata, uint16_t size);
};
```

**核心成员**：<code>i2c_write_cb</code> 是一个函数指针，用于绑定底层 I2C 写数据实现

**回调函数签名**：

```c
int i2c_write_callback(uint8_t addr,        // I2C设备7位/8位地址
                        const uint8_t *pdata, // 待发送数据缓冲区指针
                        uint16_t size);      // 待发送数据长度
```

* **功能**：底层 I2C 总线写数据实现，由用户根据硬件平台编写

```c
    }
```
